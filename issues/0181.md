## Description

The messages module shipped a batch of features (#0105–#0112) in one cycle. Sender info rows, timestamps, date dividers, link card embeds, system messages, and emoji reactions were all added together and none have automated regression coverage. A UI test suite asserts structural presence of each element type so future work on the messages thread doesn't silently break them.

Depends on #0175 (foundation).

## Regressions this suite would have caught

- **#0105** — Group chat bubbles missing sender info row. A test on a group conversation asserting `message-sender-row` exists on bubbles from other participants would have caught it.
- **#0107** — Missing per-message timestamps and date dividers. A test asserting `message-date-divider` and `message-timestamp` exist would lock in their presence.
- **#0109** — No scroll-to-bottom button or new-messages divider. A test asserting `messages-scroll-to-bottom` button exists when scrolled up would have caught it.
- **#0112** — Compose bar doesn't detect mentions, links, or hashtags. A test typing `@username` into the compose bar and asserting a mention suggestion popover appears would catch facet detection regressions.

## Test cases

All tests use the #0175 harness. `launch(script: [.selectTab(.messages)])`.

### Conversation list

- **Messages screen loads.** Assert `conversation-list-screen` exists within 5 s.
- **At least one conversation cell visible.** Assert `conversation-cell` count ≥ 1 (conditional on the test account having DMs).
- **Conversation cell contains avatar, name, and last-message preview.** Assert each `conversation-cell` has `conversation-avatar`, `conversation-name`, `conversation-preview` sub-elements.

### Conversation thread

`launch(script: [.selectTab(.messages), .openFirstConversation])`.

- **Message thread screen shows.** Assert `conversation-thread-screen` exists.
- **At least one message bubble visible.** Assert `message-bubble` count ≥ 1.
- **Sender info row present on group bubbles.** Assert `message-sender-row` exists on at least one bubble in a group conversation (skip for 1:1 threads).
- **Date divider present.** Assert `message-date-divider` exists if the thread spans more than one calendar day.
- **Compose bar present and hittable.** Assert `message-compose-bar` exists and is hittable.

### Screenshot

- `screenshot(screen: "messages-list")` — conversation list.
- `screenshot(screen: "messages-thread")` — open conversation.
- `screenshot(screen: "messages-list-dark")` and `screenshot(screen: "messages-thread-dark")`.

## Notes

- Tests requiring a real conversation require the test account to have at least one DM. Use `BLUESKY_TEST_DM_HANDLE` env var to specify the other participant; a setUp helper can create a test message via the AT Proto Chat API before the tests run.
- The `openFirstConversation` intent uses an XCUIElement tap on the first `conversation-cell` — no internal state shortcut needed since `ConversationListScreen` handles its own navigation.

## Root cause

Not a bug — this is the missing automated regression coverage for the messages module (#0105–#0112). The DM conversation list and message thread screens had no `.accessibilityIdentifier` anchors, so no UI test could assert their structure.

## Fix

Added the structural accessibility identifiers the suite needs to `BlueskyKit` (`BlueskyMessages`) and wrote `MessagesUITests.swift` on the #0175 harness:

- `ConversationListScreen` — `conversation-list-screen` on the outer container; `conversation-cell` (with `.accessibilityElement(children: .contain)`) on each row; `conversation-avatar`, `conversation-name`, `conversation-preview` on the row sub-elements.
- `MessageThreadScreen` — `conversation-thread-screen` on the outer VStack; `message-bubble` (contain) on each bubble; `message-sender-row` on the group sender header (#0105); `message-date-divider` on the per-day divider (#0107); `message-compose-bar` (contain) on the compose bar.
- `MessagesUITests` — list-loads + cell-composition tests (conversation list), thread-shows + bubble + group-sender-row + date-divider + compose-bar tests (thread), and four screenshots (list / thread, light + dark). Every test skips cleanly when credentials are absent; the conversation-dependent tests skip cleanly when the account's DM inbox is empty.

No new `UITestIntent` was added — the existing `.openFirstConversation` (selects the Messages tab) plus an XCUIElement tap on the first `conversation-cell` in the test drive the thread navigation, exactly as the issue specifies.
