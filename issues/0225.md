# 0225 — `app.bsky.feed.post` record is written without a `$type` discriminator

| | |
|---|---|
| **Status** | open |
| **Module** | BlueskyCore |
| **Platform** | All |
| **First seen** | 2026-06-11 |

## Description

The post record body sent to `createRecord` omits `$type: "app.bsky.feed.post"`. The official PDS tolerates it (collection is authoritative), but strict lexicon validators / some relay/appview paths reject record-level-`$type`-less records, and it's inconsistent with every other record this client writes.

## Evidence

`PostRecord` (Post.swift:273-305) uses synthesized Codable with no `$type` key and no custom `encode(to:)`; no call site injects one. `CreateRecordRequest.encode` (Feed.swift:227-233) writes the record verbatim. By contrast ThreadgateRecord/PostgateRecord/SelfLabels/Embed all emit explicit `$type`.

## Suggested fix

Give `PostRecord` a custom `encode(to:)` (+CodingKeys) emitting `$type = "app.bsky.feed.post"`, matching @atproto/api.
