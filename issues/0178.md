## Description

Profile screen regressions have been some of the hardest to catch manually — broken banner and avatar (#0056), content clipped on leading edge (#0155), action buttons unresponsive from notification paths (#0159). Most require navigating to a real profile over the network. A UI test suite asserts the structural elements are present, action buttons are hittable, and own-profile menu items are wired.

Depends on #0175 (foundation).

## Regressions this suite would have caught

- **#0056** — Profile banner broken, avatar placeholder broken, post cards not dark mode. A test asserting `profile-banner` and `profile-avatar` exist would have caught the missing views.
- **#0155** — Profile content clipped on leading edge (regression). A test asserting the avatar's frame origin.x > 0 would have caught the layout regression.
- **#0159** — Profile action buttons unresponsive when reached from a notification. A test navigating to a profile from the notifications path and asserting `post-action-like` is hittable would have caught it.
- **#0046** — Tapping a post author avatar doesn't navigate to their profile. A test tapping `post-author-avatar` in the feed and asserting `profile-screen` appears would have caught it.

## Test cases

All tests use the #0175 harness.

### Own profile

`launch(script: [.selectTab(.profile)])`.

- **Profile header elements present.** Assert `profile-avatar`, `profile-display-name`, `profile-handle`, `profile-followers-count`, `profile-following-count` exist.
- **Banner present.** Assert `profile-banner` exists (or `profile-banner-placeholder` if the account has no banner).
- **Posts tab loads.** Assert `profile-posts-tab` exists and is selected by default; assert at least one `post-cell` appears.
- **Menu items reachable.** Tap the profile menu (ellipsis or `profile-menu-button`). Assert `Settings`, `Saved`, `My Lists`, `Moderation` menu items exist.

### Other profile (via feed author tap)

`launch(script: [.selectTab(.home), .waitForFeedLoad(minPosts: 1)])`. Then XCUITest taps the author avatar of the first post.

- **Profile screen pushes.** Assert `profile-screen` exists after tap.
- **Follow / Unfollow button present.** Assert `profile-follow-button` exists and is hittable.
- **Back navigation works.** Tap back. Assert `profile-screen` no longer exists at top level.

### Screenshot

- `screenshot(screen: "own-profile")` from the Profile tab.
- `screenshot(screen: "other-profile")` after navigating to an author from the feed.

## Notes

- Own-profile and other-profile use the same `ProfileScreen` view; the distinction is whether `actorDID == viewerDID`. Tests should cover both paths since the conditional rendering (follow button, own-profile menu) differs.
- Accessibility identifiers need to be added to `ProfileScreen`, `ProfileHeaderView`, and the stats row.
- Profile data requires a live network call. Mark network-dependent tests accordingly.
