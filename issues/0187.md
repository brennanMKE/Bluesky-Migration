## Description

macOS mirror of #0176. Run/adapt the home-feed UI coverage on the **macOS** destination: feed loads, post cells render, and the post action buttons (like/repost/reply) are present and interactive. Account for the macOS navigation shell (sidebar + toolbar instead of the iOS bottom tab bar) and hover/click semantics.

## Scope

- Verify on `platform=macOS` via the Screenshots test plan, reusing the `post-cell` / `post-action-*` accessibility identifiers from #0176.
- Adapt feed navigation (`selectTab(.home)` on the sidebar) and any iOS-only assumptions (rubber-band scroll, etc.).
- Mirror the passing iOS checks; mark macOS-irrelevant ones clearly.

## Verification

`xcodebuild test -scheme "Bluesky (Beta)" -testPlan Screenshots -destination 'platform=macOS' BLUESKY_TEST_HANDLE=… BLUESKY_TEST_PASSWORD=…` runs the macOS home-feed tests green.

### 2026-06-10 — cross-platform tab navigation prepped

The home-feed suite already drives most navigation through the
`UITestNavigator` script (platform-agnostic). The one iOS-only assumption was
the duplicate-cells guard, which switched tabs via literal
`app.buttons["Home"]/["Search"]` — those are tab-bar `Button`s on iOS but
sidebar `cells` on the macOS `NavigationSplitView`. Added `tab(_:)` /
`tapTab(_:)` helpers to `BlueskyUITestHarness` (resolve `buttons[title]` else
`cells[title]`) and switched `testNoDuplicateCellsAfterTabSwitch` to `tapTab`,
so the suite is shell-agnostic. The remaining literal-button lookups in the
sibling suites (`Posts` / `Mentions` / `All` segmented controls, profile/menu
items) are in-screen SwiftUI controls identical on both platforms. macOS
`build-for-testing` re-verified green. Still gated on #0186's signing + TCC
prerequisites before this can actually *run* on macOS.
