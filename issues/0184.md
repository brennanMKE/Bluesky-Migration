# 0184 — Quote-with-media embeds fail to decode: `recordWithMedia` misses the nested `record` wrapper

| | |
|---|---|
| **Status** | open |
| **Module** | BlueskyCore / BlueskyFeed |
| **Platform** | All |
| **First seen** | 2026-06-10 |

## Description

Posts that quote another post *and* attach media (`app.bsky.embed.recordWithMedia`) fail to decode in both their record and view representations. The decoder falls back to `.unknown`, so these posts render in the feed without their quoted post / media. A single Mac app feed load (2026-06-10 14:07, Bluesky Beta) produced 21 error-level log entries from the `Embed` category.

## Steps to reproduce

1. Launch the Mac app and sign in.
2. Load the home feed (any feed containing a quote post with attached media).
3. Stream logs: `/usr/bin/log show --last 1h --predicate 'subsystem CONTAINS "co.sstools.Bluesky" AND messageType == 16' --style compact`

## Expected behavior

`recordWithMedia` embeds decode into `.recordWithMedia(record:media:)` in both `Embed` and `EmbedView`, and the post renders with its quoted post and media, matching the RN client.

## Actual behavior

Two paired error logs per affected post, and the embed degrades to `.unknown` (nothing rendered):

```
[co.sstools.Bluesky.beta:Embed] Failed to decode app.bsky.embed.recordWithMedia: The data couldn’t be read because it is missing.
[co.sstools.Bluesky.beta:Embed] Failed to decode $type for EmbedRecordContent: The data couldn’t be read because it is missing.
```

## Attachments

None (log lines inline above).

## Notes

Root cause — both representations in `BlueskyKit/Sources/BlueskyCore/Embed.swift` skip one nesting level on the `recordWithMedia` branch:

- **Record side** (`Embed.init(from:)`, ~line 157): for `app.bsky.embed.recordWithMedia` the code decodes the `record` key directly as a flat `EmbedRecordRef` (`uri`/`cid`). Per the lexicon, `recordWithMedia.record` is an `app.bsky.embed.record` object — the strong ref lives one level deeper at `record.record.{uri,cid}`. The `uri` key lookup fails → "data missing" → `.unknown`.
- **View side** (`EmbedView.init(from:)`, ~line 378, via `EmbedRecordView`): `EmbedRecordView.init(from:)` decodes `EmbedRecordContent` from the same decoder position, with a comment asserting "there is no nested `record` key". That holds for `app.bsky.embed.record#view` (content is directly under `record`), but for `app.bsky.embed.recordWithMedia#view` the `record` field is a full `app.bsky.embed.record#view` object containing its own nested `record` key — the outer level has no `$type`, hence the "$type … missing" error.

Fix sketch: on both `recordWithMedia` branches, unwrap the intermediate `app.bsky.embed.record` / `#view` wrapper before decoding the ref/content. Verify shapes against the RN reference: `../Bluesky-ReactNative` lexicons (`app/bsky/embed/recordWithMedia`) and `state/queries`.

Related: #0044 (missing `$type` in embedded quote record, resolved) hardened these paths to fall back to `.unknown` instead of failing the whole feed load — which is why this surfaces as silent rendering degradation plus error logs rather than a feed failure.
