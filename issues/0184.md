# 0184 — Search result rows don't navigate: SearchScreen mounted without onActorTap/onPostTap

| | |
|---|---|
| **Status** | open |
| **Module** | BlueskySearch / Bluesky-SwiftUI |
| **Platform** | All |
| **First seen** | 2026-05-25 |

## Description

Discovered while writing the search UI test suite (#0179). The Search tab in `MainTabView` mounts `SearchScreen(network:)` without supplying the `onActorTap` / `onPostTap` navigation callbacks, so tapping a People result or a post result in search does not push a profile or a thread. The result rows render but are navigational dead ends.

## Steps to reproduce

1. Run the app and open the Search tab.
2. Type a query that returns People and Post results.
3. Tap an account result, then tap a post result.

## Expected behavior

Tapping an account result pushes that user's `ProfileScreen`; tapping a post result pushes the corresponding `ThreadView` — matching the routing already wired for the feed and notifications tabs.

## Actual behavior

Nothing happens on tap; `SearchScreen` has no destination callbacks wired from the app shell.

## Notes

- The #0179 suite covers this with `testTappingAccountResultNavigatesToProfile` / `testTappingPostResultNavigatesToThread`, which currently **skip** cleanly. Wiring the callbacks here will let those tests activate.
- Fix likely mirrors the notifications-tab pattern in `Bluesky-SwiftUI/Bluesky-SwiftUI/MainTabView.swift` (hoisting `onPostTap` / `onAuthorTap` up to the app shell so `BlueskySearch` need not import `BlueskyFeed`/`BlueskyProfile`).
- Reference: `SearchScreen` init in `BlueskyKit/Sources/BlueskySearch/SearchScreen.swift`.
