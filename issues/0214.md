# 0214 — Main JSON decoder uses `.iso8601`, which rejects fractional-second timestamps

| | |
|---|---|
| **Status** | open |
| **Module** | BlueskyCore |
| **Platform** | All |
| **First seen** | 2026-06-11 |

## Description

Any response whose `Date` field carries fractional seconds (e.g. `indexedAt`/`createdAt` like `...T00:00:00.123Z`, which the appview emits) fails to decode, dropping the whole item. (Feeds currently decode, so impact may be partial/latent depending on which fields the API serves fractional.)

## Evidence

`ATProtoClient.swift:21-25` sets `dateDecodingStrategy = .iso8601`, which uses default `ISO8601DateFormatter` options (no `.withFractionalSeconds`). Lexicon types decode these as `Date` (e.g. Feed.swift:130-147 `indexedAt`/`createdAt: Date?`). The team already worked around this elsewhere: `Moderation.swift:551-562` builds an explicit `.withFractionalSeconds` formatter with fallback. Same `.iso8601` in SessionManager.swift:39 and KeychainAccountStore.swift:23.

## Suggested fix

Replace `.iso8601` with a `.custom` strategy that tries a `.withFractionalSeconds` formatter first, then falls back to the plain one (and tolerate >3 fractional digits).
