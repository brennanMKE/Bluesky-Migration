# 0212 — Message thread is always treated as "at bottom" (jump-to-newest / new-messages divider never appear)

| | |
|---|---|
| **Status** | open |
| **Module** | BlueskyMessages |
| **Platform** | All |
| **First seen** | 2026-06-11 |

## Description

In any conversation whose content exceeds the viewport (essentially all real threads), the reader is always considered at the bottom: the "Jump to newest" pill and "New messages" divider never show, and incoming messages force an auto-scroll even when the user scrolled up to read history.

## Evidence

`MessageThreadScreen.swift`: `ScrollViewportHeightKey` is written by two GeometryReaders — the inner `LazyVStack` content background (~225-232, height = full content) and the ScrollView's own background (~235-242, height = viewport). Its reducer is `max(value, nextValue())` (~1217-1222), so `viewportHeight` becomes content height once the thread overflows. `updateAtBottom` then computes `distanceFromBottom = sentinelMaxY - viewportHeight` ≤ 0, so `nowAtBottom` is always true.

## Suggested fix

Remove the inner content-background GeometryReader so only the ScrollView frame feeds `ScrollViewportHeightKey` (or give content height its own key).
