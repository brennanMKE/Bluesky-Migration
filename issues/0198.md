## Description

The Mac app uses a `NavigationSplitView` sidebar for tab navigation. It should instead use a hamburger button (`line.3.horizontal`) at the leading edge of the top bar that toggles a slide-in menu drawer over the content — matching the RN app's navigation. Fully working reference implementation in the prototype at `~/Developer/Bluesky/MacBlueskyNav` (`ContentView.swift`, `MenuDrawerView.swift`).

## Steps to reproduce

1. Launch the Mac app and sign in.
2. Observe the left side of the window: a system sidebar toggle and a persistent sidebar column.

## Expected behavior

A hamburger button at the leading toolbar position toggles a 280pt drawer that slides in from the leading edge over the content, with a dimming scrim: profile header (avatar, name, handle, follower counts) on top, then the navigation items (Explore, Home, Chat, Notifications, Feeds, Lists, Saved, Profile, Settings), then footer links. Clicking the scrim, pressing Escape, or navigating dismisses it.

## Actual behavior

macOS navigation is a `NavigationSplitView` with a `List(selection:)` sidebar (`MainTabView.swift` ~line 305, `macOSSidebar`); the system sidebar toggle occupies the leading toolbar slot.

## Notes

This is the largest of the three changes — it replaces `macOSSidebar`'s split-view structure with a `NavigationStack` + overlay drawer, and the drawer becomes how tabs are switched on macOS.

The prototype solved several non-obvious problems; mirror its solutions (`MenuDrawerView.swift`):

- Drawer is always present for animation but gated with `allowsHitTesting(isPresented)` so the closed overlay doesn't steal clicks.
- Scrim is a plain-styled `Button` (tappable *and* accessible), `opacity` animated.
- Accessibility: `accessibilityHidden(!isPresented)` so VoiceOver can't reach the offscreen drawer; `.isModal` trait when open to keep focus inside; a named "Close menu" AX action on the panel.
- Escape-to-dismiss via a hidden `.keyboardShortcut(.escape)` button inserted only while open.
- Close the drawer before pushing a destination so it isn't open on back-navigation (`ContentView.swift`).

The prototype's own `issues/` folder (0001–0009) documents the design decisions behind these — worth reading before implementing. **Do not copy screenshots from the prototype project — they are private images.** Reference its source only.

## Relation

- Pairs with: [#0196](0196.md), [#0197](0197.md) — together these adopt the prototype's RN-style navigation on macOS.

## Root cause

macOS navigation was a `NavigationSplitView` with a persistent `List(selection:)` sidebar (`macOSSidebar`) and the system sidebar toggle in the leading toolbar slot — a desktop pattern that diverges from the RN app's hamburger-toggled drawer navigation.

## Fix

Replaced `macOSSidebar` with `macOSNavigationLayout`: a single keyed `NavigationStack` with a leading-edge overlay drawer toggled by a `line.3.horizontal` hamburger at the `.navigation` toolbar placement. The existing shared `DrawerView` (built for iOS in #0150) was made cross-platform (fixed 280pt width on macOS, no bottom safe-area inset) so drawer content — profile header, nine nav rows, footer links — is identical across platforms. All of the prototype's non-obvious solutions were mirrored: always-present overlay gated by `allowsHitTesting`, plain-styled scrim `Button` with animated opacity, `accessibilityHidden` when closed, `.isModal` while open, named "Close menu" AX action, Escape via hidden `keyboardShortcut` button inserted only while open, and close-before-push. Programmatic tab switches (deep links, push routing, UI-test driver) auto-close the drawer via `resetTransientNavState()`. The UI-test harness was updated for the new layout.

State machinery intact: macOS never had independent per-tab stacks — it used (and still uses) a single NavigationStack `.id(selectedTab)` with shared destination `@State` reset by `resetTransientNavState()` on tab change. The restructure moved `.id`/`.onChange`/the FAB overlay from the detail column to the outer layout but preserved those exact semantics, so no per-tab path state was lost. Deep links, push-notification routing, and the UITestDriver flow through `selectedTab` and `resetTransientNavState()` as before; the new `showMacDrawer = false` line in `resetTransientNavState()` correctly closes the drawer on programmatic tab switches.

UI-test harness updates are sound: `waitForMainTabView` now also accepts the always-visible "Open menu" hamburger as a ready signal (necessary since drawer rows are AX-hidden when closed), and `tapTab` opens the drawer first on macOS before tapping the destination. ## Files changed

## Gotchas

- The drawer overlay must be layered after (on top of) the compose FAB overlay so the scrim covers the FAB while open; both are gated with `allowsHitTesting` so the closed drawer never steals clicks.
- macOS uses a single `NavigationStack` keyed by `.id(selectedTab)` with shared destination state — there is no per-tab path state to preserve; `resetTransientNavState()` is the choke point for programmatic tab switches and now also closes the drawer.
- The `.isModal` AX trait is inert while the container is `accessibilityHidden`, which is exactly the prototype's behavior — don't "fix" it.
