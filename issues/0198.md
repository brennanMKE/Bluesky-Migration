## Description

The Mac app uses a `NavigationSplitView` sidebar for tab navigation. It should instead use a hamburger button (`line.3.horizontal`) at the leading edge of the top bar that toggles a slide-in menu drawer over the content — matching the RN app's navigation. Fully working reference implementation in the prototype at `~/Developer/Bluesky/MacBlueskyNav` (`ContentView.swift`, `MenuDrawerView.swift`).

## Steps to reproduce

1. Launch the Mac app and sign in.
2. Observe the left side of the window: a system sidebar toggle and a persistent sidebar column.

## Expected behavior

A hamburger button at the leading toolbar position toggles a 280pt drawer that slides in from the leading edge over the content, with a dimming scrim: profile header (avatar, name, handle, follower counts) on top, then the navigation items (Explore, Home, Chat, Notifications, Feeds, Lists, Saved, Profile, Settings), then footer links. Clicking the scrim, pressing Escape, or navigating dismisses it.

## Actual behavior

macOS navigation is a `NavigationSplitView` with a `List(selection:)` sidebar (`MainTabView.swift` ~line 305, `macOSSidebar`); the system sidebar toggle occupies the leading toolbar slot.

## Notes

This is the largest of the three changes — it replaces `macOSSidebar`'s split-view structure with a `NavigationStack` + overlay drawer, and the drawer becomes how tabs are switched on macOS.

The prototype solved several non-obvious problems; mirror its solutions (`MenuDrawerView.swift`):

- Drawer is always present for animation but gated with `allowsHitTesting(isPresented)` so the closed overlay doesn't steal clicks.
- Scrim is a plain-styled `Button` (tappable *and* accessible), `opacity` animated.
- Accessibility: `accessibilityHidden(!isPresented)` so VoiceOver can't reach the offscreen drawer; `.isModal` trait when open to keep focus inside; a named "Close menu" AX action on the panel.
- Escape-to-dismiss via a hidden `.keyboardShortcut(.escape)` button inserted only while open.
- Close the drawer before pushing a destination so it isn't open on back-navigation (`ContentView.swift`).

The prototype's own `issues/` folder (0001–0009) documents the design decisions behind these — worth reading before implementing. **Do not copy screenshots from the prototype project — they are private images.** Reference its source only.

## Review

### Round 1 — 2026-06-11 — claude-opus-4-8

**Verdict: Approve**

Reviewed `git diff main...HEAD` (commits `0f598af`, `edef8ce`) plus surrounding code in `MainTabView.swift`, `DrawerView.swift`, and `BlueskyUITestHarness.swift`. Re-ran both builds independently: macOS (`platform=macOS`) and iOS Simulator (iPhone 17) — both exit 0, no errors.

The change cleanly replaces `macOSSidebar` (NavigationSplitView) with `macOSNavigationLayout` (a single keyed NavigationStack + leading overlay drawer). No dead sidebar remnants remain (the only `NavigationSplitView` left is the legitimate iPad regular-width branch at MainTabView.swift:508; the other matches are doc comments).

Spec conformance:
- Hamburger `line.3.horizontal` at `.navigation` (leading) toolbar placement; toggles the drawer with the 0.25s easeInOut animation.
- 280pt panel slides from the leading edge over content with a 0.35-opacity dimming scrim.
- Content order/parity is inherited verbatim from the shared `DrawerView` (#0150): profile header (avatar, name, handle, follower/following stats) → nine nav rows (Explore, Home, Chat, Notifications, Feeds, Lists, Saved, Profile, Settings) → footer legal links + Feedback/Help pills.
- Scrim click, Escape, and navigation all dismiss; the drawer is the sole macOS tab-switch mechanism (`DrawerView.selectTab`/`pushAfterTabSwitch` flip `selectedTab`); destinations close the drawer before pushing (`onDismiss()` runs first in both helpers, routed to `dismissMacDrawer()`).

Every mandatory prototype solution is genuinely implemented, not just claimed — verified line-by-line against `MacBlueskyNav/MenuDrawerView.swift`:
- `allowsHitTesting(showMacDrawer)` on scrim, panel, and the wrapping ZStack (so the closed overlay never steals clicks; the FAB behind it stays reachable when closed and is correctly covered by the scrim when open — drawer overlay is layered after the FAB overlay).
- Scrim is a `.plain`-styled `Button` with `value:`-animated opacity.
- `accessibilityHidden(!showMacDrawer)` when closed; `.accessibilityElement(children: .contain)` + `.isModal` while open (trait is inert when closed because the container is AX-hidden — matches the prototype exactly).
- Named "Close menu" AX action on the panel.
- Escape via a hidden `keyboardShortcut(.escape)` button inserted only inside `if showMacDrawer`.

#0196/#0197 preserved: trailing toolbar still carries only the `#` (`number`) Feeds button; compose FAB still bottom-trailing, hidden on Messages; the composer sheet is hoisted to the macOS shell `body` so the FAB reaches it on every tab after the NavigationSplitView→NavigationStack restructuring.

State machinery intact: macOS never had independent per-tab stacks — it used (and still uses) a single NavigationStack `.id(selectedTab)` with shared destination `@State` reset by `resetTransientNavState()` on tab change. The restructure moved `.id`/`.onChange`/the FAB overlay from the detail column to the outer layout but preserved those exact semantics, so no per-tab path state was lost. Deep links, push-notification routing, and the UITestDriver flow through `selectedTab` and `resetTransientNavState()` as before; the new `showMacDrawer = false` line in `resetTransientNavState()` correctly closes the drawer on programmatic tab switches.

iOS unaffected: the shared `DrawerView` change is byte-equivalent for iOS — `panelWidth` keeps the same `min(UIScreen.main.bounds.width * 0.82, 340)` value (now behind `#if os(iOS)`), and `.ignoresSafeArea(edges: .bottom)` remains iOS-only. The macOS branch adds the fixed-280pt width and drops the bottom safe-area inset, both correct for a desktop window.

UI-test harness updates are sound: `waitForMainTabView` now also accepts the always-visible "Open menu" hamburger as a ready signal (necessary since drawer rows are AX-hidden when closed), and `tapTab` opens the drawer first on macOS before tapping the destination. Minor, non-blocking note: a theoretical AX-label collision between a `tapTab("Saved")` and the Profile toolbar Menu's "Saved" item is avoided in practice because the Menu's children aren't in the AX tree while collapsed.
