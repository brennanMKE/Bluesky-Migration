## Description

macOS mirror/foundation for the UI-test automation built in #0175 (which was implemented and verified on the iOS Simulator only). This issue covers making the `UITestNavigator` driver and `BlueskyUITestHarness` work against the **macOS** app, and getting the suite to actually build-sign-run on the Mac. The macOS app uses a different navigation shell than iOS (sidebar / `NavigationSplitView`, toolbar, multi-window, hover states) rather than the iOS `TabView` + bottom tab bar, so the driver's tab/selection and push intents need a macOS path.

This issue blocks #0187–#0194 (the macOS suite mirrors).

## Scope

- **Signing (prerequisite).** The macOS test build currently fails: `Entitlement com.apple.developer.aps-environment not found and could not be included in profile`. Automatic signing can't produce a provisioning profile because no Apple ID / team is configured in Xcode (`IDEProvisioningTeams` empty). Resolve by either (a) signing the team `XV8BAAVZ6V` Apple ID into Xcode → Settings → Accounts so automatic signing provisions the Push + App-Group entitlements and registers this Mac, or (b) a local-signing test configuration (separate entitlements without Push + App Group) so the macOS app ad-hoc-signs and runs without an account. Decide and document which.
- **Driver on macOS.** Confirm `selectTab`, `tapFirstPost`, `openSettings`, `openModeration`, `openComposer`, `openBookmarks`, `openFirstConversation`, `waitForFeedLoad` drive the macOS navigation shell. Adapt `MainTabView` (or the macOS shell view) to mirror navigator state the same way it does on iOS. Note #0185 (openSettings/openModeration unreliable) likely needs handling here too.
- **Harness on macOS.** Confirm `launch`, `waitForMainTabView`, `screenshot`, `assertNoScriptError` work with the macOS window. Screenshots should capture the macOS window.
- **Run target.** `xcodebuild test -scheme "Bluesky (Beta)" -testPlan Screenshots -destination 'platform=macOS' BLUESKY_TEST_HANDLE=… BLUESKY_TEST_PASSWORD=…` produces a clean run.

## Verification

`xcodebuild test … -destination 'platform=macOS'` runs the foundation tests (`UITestNavigatorTests`, `ScreenshotTests`) green on the Mac.

## Notes

- Mirrors #0175. The app + all 9 iOS suites already **compile** for macOS (verified via `build-for-testing` with signing disabled); only the run path (signing + macOS nav) is open.
- Shared accessibility identifiers added during #0176–#0183 are platform-agnostic and should be reused.

### 2026-05-25 — signing fixed; automation-permission blocker remains

Progress (status stays `open` / in-progress):

- **Signing fixed** (Bluesky-SwiftUI commit `0c9dd12`). Root cause: the project-level `CODE_SIGN_ENTITLEMENTS` in `Build.xcconfig` applied the app's entitlements (incl. `aps-environment` / App Group) to the **UI-test target**, which can't be provisioned with a push-enabled profile — so `build-for-testing` on macOS failed even though the app target builds/runs. Fix clears `CODE_SIGN_ENTITLEMENTS` for the `Bluesky-SwiftUIUITests` Debug+Release configs; the app target keeps its real entitlements.
- **macOS test BUILD now succeeds.** `xcodebuild build-for-testing -scheme "Bluesky (Beta)" -testPlan Screenshots -destination 'platform=macOS' -allowProvisioningUpdates` → `TEST BUILD SUCCEEDED`; the app provisions via *"Mac Team Provisioning Profile: co.sstools.Bluesky.beta"*. Note: CLI runs require **`-allowProvisioningUpdates`** (the Xcode GUI does this implicitly).
- **Remaining blocker — macOS automation permission.** The test RUN fails: *"The test runner failed to initialize for UI testing. (Underlying Error: Timed out while enabling automation mode.)"* This is a macOS TCC Accessibility/Automation permission for the XCUITest runner — a one-time grant (run the UI tests once from Xcode to trigger the approval prompt, or grant Accessibility in System Settings → Privacy & Security), and the run must happen in an active GUI login session. Not a code issue. Once granted, re-run the command above (without `build-for-testing`, as `test`) to verify the foundation suites, then #0187–#0194 can proceed.
