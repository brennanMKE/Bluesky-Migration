# 0220 — `MessageThreadStore.convo` is never assigned — thread uses a stale member list

| | |
|---|---|
| **Status** | open |
| **Module** | BlueskyMessages |
| **Platform** | All |
| **First seen** | 2026-06-11 |

## Description

`viewModel.convo` is always nil, so group detection and sender/actor resolution fall back to the `convo` snapshot passed at screen init. If membership changed since the inbox row was fetched (member added/removed, group renamed), the thread renders stale data — a newly added member's avatar/name won't resolve.

## Evidence

`MessageThreadStore.swift:61` declares `convo: ConvoView?` but nothing assigns it (`load()` 72-89 sets only messages/cursor). `MessageThreadScreen.members` (365-367) is `viewModel.convo?.members ?? convo.members`, always taking the stale `?? convo.members` branch.

## Suggested fix

In `MessageThreadStore.load`, fetch `chat.bsky.convo.getConvo` and assign `self.convo` so member lookups use server-fresh membership.
