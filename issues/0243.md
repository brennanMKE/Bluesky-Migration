## Description

The Mac app's DM compose bar has a photo-picker button, but using it does not result in an image being sent. Exact failure point not yet determined (picker not opening vs. image selected but send failing silently).

## Steps to reproduce

1. Launch the Mac app and sign in.
2. Open Messages and enter a conversation.
3. Click the photo button in the compose bar and select an image.

## Expected behavior

The selected image uploads and appears as an image message in the conversation for both participants, as in the RN client.

## Actual behavior

User report: the button exists, "but when I tried it it did not work." No image message appears in the conversation.

## Notes

Pipeline under suspicion, in order:

1. `MessageThreadScreen.composeBar` → `PhotosPicker` → `onChange(of: selectedPhoto)` → `sendImage(_:)` (`MessageThreadScreen.swift` ~lines 533–596). `loadTransferable(type: Data.self)` failures surface an alert — did the user see one? If nothing visible happened, the failure is likely past this point.
2. `MessageThreadViewModel.sendImageAttachment(data:mimeType:)` → `MessageThreadStore.sendImageAttachment(data:mimeType:convoId:)` (`MessageThreadStore.swift` line 144) — check what this actually does: blob upload via `com.atproto.repo.uploadBlob` must go to the **PDS** (no chat proxy header), while the `chat.bsky.convo.sendMessage` embed call must carry the proxy header. A mismatch here would fail server-side; check logs for errors.
3. Note: chat image embeds in the RN client send `embed: $type app.bsky.embed.images` inside the message — verify the Swift message body matches the lexicon.

First diagnostic: reproduce while streaming logs (`/usr/bin/log show --last 5m --predicate 'subsystem == "co.sstools.Bluesky.beta" AND messageType == 16' --style compact`) to see where the pipeline stops.
