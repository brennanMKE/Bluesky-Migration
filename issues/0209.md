# 0209 — Deep links to a profile or post are dropped / route to the wrong screen

| | |
|---|---|
| **Status** | open |
| **Module** | Bluesky-SwiftUI |
| **Platform** | All |
| **First seen** | 2026-06-11 |

## Description

Opening `https://bsky.app/profile/<handle>` (or `bluesky://profile/<handle>`) just selects the Profile tab (the viewer's own profile) instead of the linked actor; `/profile/<handle>/post/<rkey>` links are not handled at all and fall through to a no-op.

## Evidence

`handleDeepLink(_:)` (MainTabView.swift ~1148-1160) switches on the trimmed path: `notifications`, `messages/chat`, and `default: if path.hasPrefix("profile") { selectedTab = .profile }`. It never parses the handle/DID, never sets `feedProfileDID`, and has no post/thread branch — the rkey is discarded. `selectedTab = .profile` routes to the viewer's own profile.

## Suggested fix

Parse path segments: for `profile/<actor>` resolve to a DID and set `feedProfileDID` after routing to a tab hosting the profile destination; for `profile/<actor>/post/<rkey>` build the `at://` ATURI and set `threadURI`. Mirror RN's `convertBskyAppUrlIfNeeded` route table.
