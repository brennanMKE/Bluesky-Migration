## Description

Opening the Messages tab fails: both the conversation list fetch and the message-requests inbox fetch error with `ATError.xrpc(code: "MethodNotImplemented", message: "Method Not Implemented")`. This is the response a PDS gives for `chat.bsky.*` calls when the `atproto-proxy: did:web:api.bsky.chat#bsky_chat` header is missing, yet `ATProtoClient.applyProxyHeader` exists and appears to cover this case — so either the header isn't reaching the wire, or something else is wrong. Possibly a regression: Module 11 DM live validation (#0033) previously passed.

## Steps to reproduce

1. Launch the Mac app (Beta scheme) and sign in.
2. Open the Messages tab.
3. Stream logs: `/usr/bin/log show --last 5m --predicate 'subsystem == "co.sstools.Bluesky.beta" AND messageType == 16' --style compact`

## Expected behavior

Conversation list and requests inbox load via the chat service proxy, as in the RN client (`DM_SERVICE_HEADERS` in `src/lib/constants.ts`).

## Actual behavior

```
[co.sstools.Bluesky.beta:ConversationStore] convos fetch error: BlueskyCore.ATError.xrpc(code: "MethodNotImplemented", message: "Method Not Implemented")
[co.sstools.Bluesky.beta:ConversationStore] request convos fetch error: BlueskyCore.ATError.xrpc(code: "MethodNotImplemented", message: "Method Not Implemented")
```

(Bluesky Beta run 2026-06-10 14:24, PID 15218.)

## Notes

Code state at filing: `BlueskyNetworking/ATProtoClient.swift` — `applyProxyHeader(_:lexicon:)` (~line 199) sets `atproto-proxy: did:web:api.bsky.chat#bsky_chat` for any lexicon with prefix `chat.bsky.`, and `buildGetRequest` / `buildPostRequest` / `buildUploadRequest` all call it. `ConversationStore.swift` fetches via `network.get(lexicon: "chat.bsky.convo.listConvos", …)`. So the obvious cause (header never added) is not visibly true in source.

Investigation leads, in order:

1. Reproduce with `curl` against `https://bsky.social/xrpc/chat.bsky.convo.listConvos` using the stored access JWT — once with and once without the `atproto-proxy` header — to confirm which side is failing.
2. Check whether the signed-in account uses an **app password without DM access**, and what error that actually yields vs. `MethodNotImplemented`.
3. Check the 401-auto-refresh retry path in `ATProtoClient` — does the retried request preserve the proxy header, or is it rebuilt/copied in a way that drops it?
4. Verify the header survives any request mutation between build and send (e.g. interception, redirects).
5. Compare against RN: `src/lib/constants.ts` (`DM_SERVICE_HEADERS`) and the chat query setup in `src/state/queries/messages/`.

Related: #0033 (Module 11 DM live validation, resolved) — if DMs worked then, bisect what changed in `ATProtoClient` or `ConversationStore` since.
