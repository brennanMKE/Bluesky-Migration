## Description

In a DM conversation on iPhone, the compose bar offers no way to send an image. The Mac app shows a photo-picker button in the same compose bar, so this is a platform parity gap — and an unexplained one, since the photo button is not platform-gated in source.

## Steps to reproduce

1. Launch the iPhone app and sign in.
2. Open Messages and enter a conversation.
3. Look at the compose bar at the bottom.

## Expected behavior

A photo-attachment button appears next to the text field (as on macOS), opening the photo library picker and sending the selected image, matching the RN client's DM composer.

## Actual behavior

User report: "the iPhone app does not have an option to send images but I see the Mac app has a button to pick a photo."

## Notes

`MessageThreadScreen.composeBar` (`BlueskyKit/Sources/BlueskyMessages/MessageThreadScreen.swift` ~line 533) builds `PhotosPicker(selection:matching:)` with a `photo` SF Symbol label and **no `#if os(macOS)` gate**, so the button should render on iOS too. First step is to find out why it doesn't: is `MessageThreadScreen` the screen actually presented on iPhone, is the button rendered but invisible/zero-sized, or does an iOS-specific layout path omit `composeBar`?
