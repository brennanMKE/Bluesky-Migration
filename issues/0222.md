# 0222 — Reading a thread never clears the inbox unread badge

| | |
|---|---|
| **Status** | open |
| **Module** | BlueskyMessages |
| **Platform** | All |
| **First seen** | 2026-06-11 |

## Description

Opening a conversation marks it read server-side, but the conversation-list row's unread badge and `unreadCount` stay stale until a full inbox refresh.

## Evidence

`MessageThreadStore.load` calls `markRead` (line 84) which POSTs `chat.bsky.convo.updateRead` (273-280) and discards the returned `ConvoResponse`. The separate `ConversationStore` that owns `convos`/`unreadCount` (ConversationStore.swift:34) is never notified; `ConvoRow` renders the stale `convo.unreadCount` (ConversationListScreen.swift:203-206).

## Suggested fix

Propagate the read event so the shared `ConversationStore` zeroes that convo's `unreadCount` (callback/shared store, or re-read on return).
