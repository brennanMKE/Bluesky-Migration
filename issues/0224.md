# 0224 — Composer character count uses unicode scalars instead of grapheme clusters

| | |
|---|---|
| **Status** | open |
| **Module** | BlueskyComposer |
| **Platform** | All |
| **First seen** | 2026-06-11 |

## Description

The 300-char limit is computed over Unicode scalars, so multi-scalar graphemes (emoji, ZWJ family/flag sequences, combining marks) are over-counted: a post well under 300 graphemes is wrongly flagged over-limit and blocked, and the remaining-count UI is wrong. Diverges from RN, which counts graphemes.

## Evidence

`ComposerViewModel.swift:130-131` — `characterCount: Int { text.unicodeScalars.count }` and `isOverLimit { characterCount > 300 }`. RN measures `graphemeLength` vs `MAX_GRAPHEME_LENGTH = 300`; Swift's grapheme count is `text.count`.

## Suggested fix

Use `text.count` (grapheme clusters) for the 300 limit; for full parity count over the link-shortened richtext and enforce the 3000-byte UTF-8 cap separately.
