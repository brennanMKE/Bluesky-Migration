# 0216 — `networkBecameViable` is broadcast but has no subscribers — no auto-refresh on reconnect

| | |
|---|---|
| **Status** | open |
| **Module** | Bluesky-SwiftUI |
| **Platform** | All |
| **First seen** | 2026-06-11 |

## Description

When connectivity returns after an offline period, nothing re-fetches: the offline banner hides but feeds/notifications stay stale until a manual pull-to-refresh.

## Evidence

`observePathStatus()` posts `.networkBecameViable` on not-viable→viable (MainTabView.swift ~221-223). A repo-wide grep finds only the declaration (PushRouter.swift:24) and this single post — no `publisher(for:)`/`addObserver` anywhere. The documented 'view models observe this to refresh' contract has zero implementers. (Known deferred follow-up noted in #0059.)

## Suggested fix

Have FeedStore/NotificationsStore subscribe to `.networkBecameViable` and re-fetch (or drive refresh off the path-status stream directly); remove the dead notification if intentionally deferred.
