# 0232 — Deleting a muted word without a server `id` can remove unrelated duplicates

| | |
|---|---|
| **Status** | open |
| **Module** | BlueskyModeration |
| **Platform** | All |
| **First seen** | 2026-06-11 |

## Description

Deleting one muted word can also remove a second entry sharing the same value and targets (e.g. two 'spoilers' entries with different expirations/actorTarget).

## Evidence

`MutedWordsViewModel.remove` (MutedWordsScreen.swift:362-370): when `entry.id == nil` it does `entries.removeAll { $0.value == entry.value && $0.targets == entry.targets }`, matching every entry with that value/targets. New entries are created without an `id` (145-150) and aren't re-fetched before the next delete, so duplicates are indistinguishable; the whole array is then written via putPreferences.

## Suggested fix

Disambiguate beyond value+targets when `id` is missing (include expiresAt/actorTarget, or remove by reversed display index), or assign a stable client-side id on add.
