# 0219 — Switching search result tabs while a search is in flight drops the new tab's search

| | |
|---|---|
| **Status** | open |
| **Module** | BlueskySearch |
| **Platform** | All |
| **First seen** | 2026-06-11 |

## Description

After typing a query, quickly tapping a different result tab (People → Posts/Feeds) can leave the new tab empty or showing the previous tab's data — its search silently never runs.

## Evidence

Tab strip fires a fresh search on change (SearchScreen.swift:171-173). `SearchStore.search` starts with `guard !q.isEmpty, !isLoading else { return }` (SearchStore.swift:67). The debounced typeahead and the tab-switch search share one global `isLoading`, so a switch while the prior request is in flight hits `!isLoading` and returns without fetching.

## Suggested fix

Don't gate cross-tab/fresh searches on a single `isLoading`; track the in-flight request's tab (or a request token) and supersede rather than drop. Per-tab loading state (as ProfileStore uses) also fixes it.
