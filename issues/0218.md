# 0218 — Removing the active account signs the user out even when other accounts exist

| | |
|---|---|
| **Status** | open |
| **Module** | BlueskyAuth |
| **Platform** | All |
| **First seen** | 2026-06-11 |

## Description

Removing the currently-active account from the picker drops to the login screen even when other signed-in accounts remain, instead of falling back to one (RN promotes the next available account).

## Evidence

`removeAccount(did:)` (SessionManager.swift:405-413): when removing the active account it sets `currentAccount = nil` and `setCurrentDID(nil)` but never picks a replacement from remaining `accounts`. The RootView gate then shows login despite valid sessions. Called directly from AccountPickerView.swift:113.

## Suggested fix

After removing the active DID, if `accounts` is non-empty, resume/switch to the first remaining account (persist its DID) before falling back to signed-out; only clear when none remain.
