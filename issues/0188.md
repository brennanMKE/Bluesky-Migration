# 0188 — Create a distinct Beta app icon so dev/test builds are visually distinguishable

| | |
|---|---|
| **Status** | open |
| **Module** | Bluesky-SwiftUI / Build / Config |
| **Platform** | All |
| **First seen** | 2026-06-10 |

## Description

The Beta and Prod build schemes (#0173) produce apps with different bundle IDs and names ("Bluesky Beta" vs "Bluesky"), but both use the same app icon, so the two builds are indistinguishable in the Dock, Home Screen, and app switcher. Create a badged Beta variant of the app icon and wire it up so the Beta scheme builds with it automatically.

## Steps to reproduce

1. Build and run the `Bluesky (Beta)` scheme and the `Bluesky (Prod)` scheme.
2. Compare the two apps in the Dock / Applications folder.

## Expected behavior

The Beta build carries a visually distinct icon (e.g. a "BETA" banner or alternate tint over the standard icon) on iOS, iPadOS, and macOS; the Prod build keeps the standard icon. Selecting a scheme is the only step — no manual icon swapping.

## Actual behavior

Both schemes build with the identical icon (`AppIcon-iOS` / `AppIcon-macOS` per `Configuration/Build.xcconfig`); only the app name distinguishes them.

## Notes

Recommended approach — since the xcconfig layering from #0173 already exists, no copy script is needed:

1. Create badged icon sets in the asset catalog: `AppIcon-iOS-Beta.appiconset` and a macOS Beta counterpart (derive from the existing art in `Assets.xcassets/AppIcon-iOS.appiconset` plus a beta badge; see the `xcode-app-icons` skill for size/scale requirements).
2. Override in `Configuration/Beta.xcconfig`:
   ```
   ASSETCATALOG_COMPILER_APPICON_NAME[sdk=iphone*] = AppIcon-iOS-Beta
   ASSETCATALOG_COMPILER_APPICON_NAME[sdk=macos*] = AppIcon-macOS-Beta
   ```
   `Prod.xcconfig` keeps the defaults from `Build.xcconfig`. Both icon sets ship in the catalog; the build setting picks the right one, so nothing is generated at build time and `.gitignore` needs no changes.
3. While in there, verify the **macOS icon asset actually exists**: `Build.xcconfig` references `AppIcon-macOS`, but a `find` on 2026-06-10 located only `AppIcon-iOS.appiconset` in the catalog. If `AppIcon-macOS` is missing, the macOS build is using a default/empty icon — fix as part of this work (related: #0153, which populated the catalog).

Alternative (the heavier `set-environment.sh` copy pattern with gitignored icon files) is not needed given the xcconfig override does the job declaratively.
