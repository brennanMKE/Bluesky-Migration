## Description

The Settings and Moderation screens were implemented in a large batch (#0113–#0124, #0134–#0138). Each screen is a navigation tree of preference toggles, lists, and sub-screens. A UI test suite asserts each top-level destination in the settings tree is reachable and its root element is visible, so refactors to `SettingsScreen` or `ModerationScreen` that accidentally drop a sub-screen destination fail immediately.

Depends on #0175 (foundation).

## Regressions this suite would have caught

- **#0113** — Account settings was a stub. A test asserting `settings-account-screen` exists and has `settings-email-row`, `settings-password-row` would have caught the stub.
- **#0114** — Privacy & security missing inline 2FA toggle. A test asserting `settings-2fa-toggle` exists in the Privacy section would lock it in.
- **#0115** — Notification settings missing per-type sub-screens. A test asserting each notification type (likes, follows, reposts, mentions, quotes, replies) has a navigation row would catch omissions.
- **#0116 / #0117 / #0118 / #0120 / #0121 / #0122** — Various settings sub-screens missing. A reachability test for each destination catches future regressions.
- **#0134** — Mutes/Blocks lists had no search field. A test asserting `moderation-mutes-search-field` exists locks it in.

## Test cases

All tests use the #0175 harness.

### Settings root reachability

`launch(script: [.selectTab(.profile), .openSettings])`.

- **Settings screen appears.** Assert `settings-screen` exists within 2 s.
- **Account row navigates to account settings.** Tap `settings-account-row`. Assert `settings-account-screen` pushes.
- **Privacy & Security row navigates.** Back, tap `settings-privacy-row`. Assert `settings-privacy-screen` pushes.
- **Notifications row navigates.** Back, tap `settings-notifications-row`. Assert `settings-notifications-screen` pushes.
- **Appearance row navigates.** Back, tap `settings-appearance-row`. Assert `settings-appearance-screen` pushes.
- **Language row navigates.** Back, tap `settings-language-row`. Assert `settings-language-screen` pushes.
- **Accessibility row navigates.** Back, tap `settings-accessibility-row`. Assert `settings-accessibility-screen` pushes.
- **About row navigates.** Back, tap `settings-about-row`. Assert `settings-about-screen` pushes.

### Moderation reachability

`launch(script: [.selectTab(.profile), .openModeration])`.

- **Moderation screen appears.** Assert `moderation-screen` exists within 2 s.
- **Muted Accounts row navigates.** Tap `moderation-mutes-row`. Assert `moderation-mutes-screen` pushes. Assert `moderation-mutes-search-field` exists.
- **Blocked Accounts row navigates.** Back, tap `moderation-blocks-row`. Assert `moderation-blocks-screen` pushes.
- **Content Filters row navigates.** Back, tap `moderation-content-filters-row`. Assert `moderation-content-filters-screen` pushes.

## Notes

- Settings screens are navigation-destination-based (not tab-based), so reachability tests are the primary regression check — structural assertionson each sub-screen's content belong in dedicated tests once the sub-screens stabilize.
- Sign Out is present in Settings. Test code must never tap it — add an assertion that `settings-sign-out-button.isEnabled == true` (presence check only) without actually tapping.
