## Description

The Settings and Moderation screens were implemented in a large batch (#0113–#0124, #0134–#0138). Each screen is a navigation tree of preference toggles, lists, and sub-screens. A UI test suite asserts each top-level destination in the settings tree is reachable and its root element is visible, so refactors to `SettingsScreen` or `ModerationScreen` that accidentally drop a sub-screen destination fail immediately.

Depends on #0175 (foundation).

## Regressions this suite would have caught

- **#0113** — Account settings was a stub. A test asserting `settings-account-screen` exists and has `settings-email-row`, `settings-password-row` would have caught the stub.
- **#0114** — Privacy & security missing inline 2FA toggle. A test asserting `settings-2fa-toggle` exists in the Privacy section would lock it in.
- **#0115** — Notification settings missing per-type sub-screens. A test asserting each notification type (likes, follows, reposts, mentions, quotes, replies) has a navigation row would catch omissions.
- **#0116 / #0117 / #0118 / #0120 / #0121 / #0122** — Various settings sub-screens missing. A reachability test for each destination catches future regressions.
- **#0134** — Mutes/Blocks lists had no search field. A test asserting `moderation-mutes-search-field` exists locks it in.

## Notes

- Settings screens are navigation-destination-based (not tab-based), so reachability tests are the primary regression check — structural assertionson each sub-screen's content belong in dedicated tests once the sub-screens stabilize.
- Sign Out is present in Settings. Test code must never tap it — add an assertion that `settings-sign-out-button.isEnabled == true` (presence check only) without actually tapping.

## Root cause

This is a test-coverage gap, not a product bug. The Settings (`SettingsScreen`,
`AccountSettingsScreen`) and Moderation (`ModerationScreen`, `MutesScreen`,
`BlocksScreen`, `ContentFilterSettingsScreen`) navigation trees had no UI tests
and carried no accessibility identifiers, so a refactor dropping a sub-screen
destination would not be caught automatically.

Two facts surfaced while building the suite:

1. The screen `List`/`Form` roots needed `.accessibilityElement(children: .contain)`
   alongside their `.accessibilityIdentifier(...)` to surface as a single
   queryable element (bare `List` identifiers were not addressable from
   XCUITest) — the same pattern `ProfileScreen` already uses.
2. The #0175 `openSettings` / `openModeration` driver intents push via
   `navigationDestination(isPresented:)` from an `onChange`, which (verified
   empirically) does not reliably fire across the iOS tab-content rebuild — the
   Profile tab rendered but Settings never pushed. The real user path (the
   own-profile overflow menu → Settings / Moderation) pushes deterministically,
   so the suite drives that instead.

## Fix

- **BlueskyKit (`e592da9`)** — added `.accessibilityIdentifier(...)` (paired with
  `.accessibilityElement(children: .contain)` on roots) to: `SettingsScreen`
  (`settings-screen` + every row), `AccountSettingsScreen`
  (`account-settings-screen`), `ModerationScreen` (`moderation-screen` + hub
  rows), `MutesScreen` (`moderation-mutes-screen`), `BlocksScreen`
  (`moderation-blocks-screen`), `ContentFilterSettingsScreen`
  (`moderation-content-filters-screen`).
- **Bluesky-SwiftUI (`b39b745`)** — added `SettingsModerationUITests` (14
  tests). Reaches both hubs via the own-profile menu; asserts root +
  destination reachability; sub-screen pushes asserted by navigation title;
  off-screen `List` rows scrolled into view before tapping. Sign Out is
  presence/enabled-checked only and never tapped. Per the side-effect caution
  the suite never signs out, deactivates/deletes, submits a report,
  mutes/blocks anyone, or toggles a network-writing control. Each test skips
  cleanly without credentials; the mutes search-field check skips on an empty
  list rather than failing. New class auto-runs via `Screenshots.xctestplan`
  (file-system-synchronized test group — no `project.pbxproj` edit needed).
