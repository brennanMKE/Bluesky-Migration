## Description

The Search screen combines discovery (trending topics, suggested accounts) with full-text and user search. Dark mode was broken on search result post cards (#0051). Trending topics (#0026) and hashtag views (#0027) were missing features that were added but never regression-tested. A UI test suite asserts the discovery surface loads, search returns results, and result cards render correctly.

Depends on #0175 (foundation).

## Regressions this suite would have caught

- **#0051** — Search result post cards had white background in dark mode. A screenshot test in dark mode would have caught it immediately.
- **#0026** — Trending topics section missing. A test asserting `search-trending-section` exists on the discovery tab locks in its presence.
- **#0027** — Hashtag and topic views missing. A test tapping a trending topic and asserting a results list appears would catch the wiring.

## Test cases

All tests use the #0175 harness. `launch(script: [.selectTab(.search)])`.

### Discovery surface

- **Search screen loads with discovery content.** Assert `search-screen` exists. Assert `search-trending-section` or at least one `search-suggested-account` cell is visible within 5 s.
- **Search field is present and focusable.** Assert `search-field` exists and is hittable. Tap it; assert keyboard appears (or field has focus accessibilityTrait).

### Search results

- **Typing in the search field returns results.** Type "bluesky" into `search-field`. Assert at least one result cell appears within 5 s.
- **Result post cards have correct background in dark mode.** Covered by screenshot below.
- **Tapping a result post navigates to thread.** Tap first `post-cell` in results. Assert `thread-focal-post` appears.
- **Tapping a result account navigates to profile.** Tap first `search-account-result`. Assert `profile-screen` appears.

### Screenshot

- `screenshot(screen: "search-discovery")` — before typing, showing trending / suggested.
- `screenshot(screen: "search-results")` — after typing a query with results.
- `screenshot(screen: "search-discovery-dark")` and `screenshot(screen: "search-results-dark")`.

## Notes

- Search results require a live network connection and are non-deterministic. Assert existence (≥ 1 result) rather than exact counts.
- The trending topics section may not always have data (e.g. test PDS instance). Consider using `BLUESKY_TEST_SKIP_TRENDING=1` to skip that assertion in environments without trending data.

## Root cause

Not a defect — this is the missing search/discovery UI test suite called for after the #0175 foundation and the #0176–#0178 suites. `SearchScreen` carried no accessibility identifiers, so the discovery surface, the search field, the result-tab strip, and result rows had no stable anchors for an out-of-process XCUITest to assert on.

## Fix

- **BlueskyKit (`SearchScreen.swift`)** — added six `.accessibilityIdentifier(...)` anchors: `search-screen` (root), `search-field` (the query `TextField`), `search-trending-section` (trending header), `search-suggested-account` (suggested-actor rows), `search-tab-strip` (the People/Posts/Feeds segmented picker), and `search-account-result` (People-tab result rows). Post results already render `PostCard`, which carries `post-cell`.
- **Bluesky-SwiftUI (`SearchUITests.swift`)** — new `XCTestCase` built on the #0175 harness, launched via `launch(script: [.search])`. Covers: discovery loads (trending section or suggested account); search field present + focusable (types a distinctive token and confirms the value reflects it); typing "bluesky" returns ≥ 1 result; the result-tab strip switches People → Posts and surfaces `post-cell`; tapping an account result pushes `profile-screen`; tapping a post result pushes `thread-focal-post`; plus light/dark discovery and results screenshots.
- A SwiftUI `TextField`'s `.accessibilityIdentifier` does not reliably propagate to the queryable `.textField` element, so the suite's `searchField()` helper tries the identifier-keyed text-field/search-field/text-view queries first and then falls back to the sole text-entry control on the Search screen.

No new `UITestNavigator` intent was needed — the existing `.selectTab(.search)` (`.search`) reaches the screen, and all in-screen interaction is driven via `XCUIElement` typing/tapping.
