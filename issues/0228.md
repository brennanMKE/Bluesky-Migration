# 0228 — Profile relationship mutations (follow/block/mute) lack an in-flight guard

| | |
|---|---|
| **Status** | open |
| **Module** | BlueskyProfile |
| **Platform** | All |
| **First seen** | 2026-06-11 |

## Description

Double-tapping mute/follow/block fires duplicate create/delete calls; an interleaved failure can revert to a stale `original` snapshot and leave the UI inconsistent with the server.

## Evidence

Unlike the per-post like/repost/bookmark paths which dedupe via in-flight Sets (ProfileStore.swift:438-462), `follow/unfollow/block/unblock/mute/unmute` (260-434) have no guard. Each captures `let original = self.profile` and reverts on catch; two overlapping calls make the second capture the first's optimistic state as its `original`.

## Suggested fix

Add an in-flight guard (Bool/Set keyed on the action) mirroring the per-post pattern, ignoring re-entrant taps until the call resolves.
