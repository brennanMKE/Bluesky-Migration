## Description

The custom bottom tab bar on the iPhone (from #0071) has a layout problem on the **Profile-tab-selected** state. The trailing avatar tab item shows a thick blue ring around the avatar that's substantially larger than the other tab icons, throwing the tab bar's visual rhythm off:

- The four leading tabs (Home / Search / Chat / Notifications) render at one icon size with normal spacing.
- The trailing Profile tab's selected-state ring is bigger than those icons, so the avatar+ring takes up more horizontal space than its slot allows.
- Even spacing across the five tabs is broken — the avatar visually "leans" trailing.

The RN reference (attached, image #12 in the parent dispatch) shows the same five-tab bar with an evenly-spaced layout: when the Home tab is the active one in RN, the active state is a slight tint, not an oversized ring. There's no avatar in the RN bottom tab bar — it shows a profile silhouette icon.

## Steps to reproduce

1. Run the SwiftUI app on iPhone.
2. Tap the Profile tab so it becomes the active tab.
3. Observe the avatar is rendered with a thick blue ring at a larger size than the other tab icons.
4. Switch to any other tab; observe the same avatar shrinks and the ring goes away — confirming the issue is the selected-state styling, not the avatar source itself.

## Expected behavior

- Every tab icon (including the Profile avatar) renders at the same target size (~28pt for the icon area, ~32pt total slot height) regardless of selected state.
- Selected state is a subtle highlight (a tint change on the icon, or a small underline / dot below it — whichever RN uses), not a thick ring that changes the icon's effective size.
- All five slots are evenly spaced across the bar's width.

## Actual behavior

Profile tab selected-state ring is too thick and the avatar pixel size scales up, breaking the tab bar's rhythm.

### 2026-06-10 — custom tab bar now exists on main

The 2026-05-12 bail note is obsolete: the #0071 custom tab bar now
lives on `main` in `Bluesky-SwiftUI/Bluesky-SwiftUI/MainTabView.swift`

below was applied against that implementation.

## Root cause

`iosTabBarLabel(for:isActive:)` in `MainTabView.swift` rendered the
Profile slot as a 28pt `AvatarView` with, when selected, a 2pt
brand-blue (`theme.colors.link`) `strokeBorder` ring at 30×30pt —
bigger than the other glyphs (SF Symbols at 24pt font), so the
avatar+ring broke the bar's icon-size rhythm. RN's
`src/view/shell/bottom-bar/BottomBar.tsx` at the baseline commit
(`46b8a58`) instead uses `iconWidth = 28` and draws the avatar at
`iconWidth - 2` (26px) unselected / `iconWidth - 3` (25px) selected
inside a circular wrapper with a 1px border colored
`t.atoms.text.color` (primary text color, not blue), keeping the
slot's footprint at 28px in both states. RN also tints every bottom-bar
icon with the primary text color in both states — selection is conveyed
purely by the filled glyph variant — whereas the SwiftUI bar tinted the
active icon link-blue and inactive icons `textSecondary`.

## Fix

Brought `iosTabBarLabel` / `iosCustomTabBar` to RN parity (px → pt 1:1):
avatar 26pt unselected, 25pt selected with a 1pt
`theme.colors.textPrimary` `strokeBorder` ring at 27×27pt, both inside
a fixed 28×28pt slot frame; all icons now tint `theme.colors.textPrimary`
in both states with the existing outline/filled swap conveying
selection; added the bar's 8pt horizontal padding (RN
`BottomBarStyles.bottomBar` `paddingLeft/Right: tokens.space.sm` = 8).
Even spacing was already provided by `HStack(spacing: 0)` with
`.frame(maxWidth: .infinity)` per button (RN `Btn` is `flex: 1`).
Verification screenshots also exposed feed content showing through
below the bar in the home-indicator region, so the bar's background now
carries `.ignoresSafeArea(edges: .bottom)` (RN's bar is opaque with
`paddingBottom: clamp(insets.bottom, 15, 60)`).

## Gotchas

- RN's selected-state ring is **not** brand blue — `onProfile` sets
  `borderColor: t.atoms.text.color`, so it's black in light mode and
  white in dark mode. Easy to get wrong from memory.
- RN's bottom-bar icons do not change color on selection at all
  (`t.atoms.text` in both branches); only the glyph swaps
  outline ↔ filled. A blue active tint is a web-Bluesky/iOS-default
  habit, not RN mobile behavior.
- The avatar is *smaller* when selected (25px vs 26px) in RN — the 1px
  ring eats into the same 28px footprint rather than growing outside it.
- `sips --cropOffset` silently no-ops when offset + crop height exceeds
  the image bounds; keep the crop window fully inside the image.
