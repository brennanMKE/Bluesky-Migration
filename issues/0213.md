# 0213 — Replies to a reply set `reply.root` to the parent, mis-threading deep threads

| | |
|---|---|
| **Status** | open |
| **Module** | BlueskyComposer |
| **Platform** | All |
| **First seen** | 2026-06-11 |

## Description

Replying to a post that is itself a reply produces a post record whose `reply.root` points to the immediate parent instead of the true thread root, so appviews/clients that key off `reply.root` group it under the wrong root and thread reconstruction/notifications break.

## Evidence

`ComposerStore.swift:340` — `let reply = replyTo.map { ReplyRef(root: $0, parent: $0) }`. `replyTo` is the parent `PostRef` only (passed from ThreadView/FeedView/ProfileScreen). AT Proto requires `reply.root` = thread root; when the parent is itself a reply, root must be inherited from `parent.record.reply.root`. Confirmed firsthand (line 340).

## Suggested fix

Pass the parent `PostView` (or its `record.reply`) into the composer and compute `root = parent.record.reply?.root ?? PostRef(parent)`, mirroring RN's `getReplyRef`.
