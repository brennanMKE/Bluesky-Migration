## Description

`screenshot.sh` in `Bluesky-SwiftUI/` was copied from another project and still references a hardcoded bundle ID (`co.sstools.Issues.beta`) that does not exist in this app. The script also only captures a single window snapshot with no mechanism for iterating across multiple screens.

A working automated screenshot workflow would allow rapid visual regression checks and issue documentation across the full screen surface — home feed, thread view, profile, search, notifications, messages, composer, settings, and moderation.

This issue depends on [#0173](0173.md) (beta bundle ID via xcconfig schemes), because the script should target the beta build (`co.sstools.Bluesky.beta`) so screenshot sessions run in an isolated container and do not interfere with production state.

## Expected behavior

- Running `./screenshot.sh` (or a companion driver script) captures a screenshot of the currently visible Bluesky Beta window and saves it to `screenshots/` with a timestamped filename.
- An optional iteration mode (`./screenshot.sh --all`) navigates through a predefined list of screens via `xcrun simctl` or UI scripting (AppleScript / `osascript`) and captures one screenshot per screen.
- Screenshots are saved as `screenshots/<screen-name>_<timestamp>.png`.
- The script exits with a clear error if the beta app is not running.

## Steps to reproduce

1. Open `Bluesky-SwiftUI/screenshot.sh`.
2. Observe the bundle ID is `co.sstools.Issues.beta` — does not match the Bluesky app.
3. Run `./screenshot.sh` with the Bluesky Beta app running — script finds no window and exits with a warning.

## Actual behavior

Script always exits with "Warning: Themes window not found — is the app running?" because the `windows` lookup uses the wrong bundle ID.

## Approach

1. **Fix the bundle ID** in `screenshot.sh`: replace `co.sstools.Issues.beta` with `co.sstools.Bluesky.beta`. This requires #0173 to be implemented first so the beta build actually uses that bundle ID.

2. **Add a `--screen` argument** so the script can be called once per screen in a loop:
   ```sh
   ./screenshot.sh --screen home
   ./screenshot.sh --screen thread
   ```

3. **Add a screen list and driver loop** — either inline in `screenshot.sh` or as a separate `screenshots-all.sh` — that:
   - Ensures the Beta scheme is active (`./scripts/set-environment.sh Beta`)
   - Launches the app (simulator or device)
   - Navigates to each screen via deep link or UI scripting
   - Calls `screenshot.sh --screen <name>` for each
   - Prints a summary of saved files

4. **Update the `windows` lookup** to use the correct bundle ID constant. Consider extracting it to a variable at the top of the script so it stays in sync with `Configuration/Beta.xcconfig`.

## Notes

- The `windows` CLI tool used in `screenshot.sh` is a third-party utility. Confirm it is available in the project's toolchain, or replace with `screencapture -l $(GetWindowID "Bluesky Beta")` using the standard `GetWindowID` helper.
- For simulator-based iteration, `xcrun simctl io booted screenshot` is simpler and does not require a window ID lookup.
- The per-screen deep-link navigation approach requires the app to register `bluesky://` URL handlers for each key destination — verify these exist or plan to add them.
- Screenshots directory should be gitignored.
- See #0173 for the xcconfig beta/prod split this script depends on.

## Root cause

`screenshot.sh` was copied from another project (`co.sstools.Issues.beta`) and never updated to match the Bluesky bundle ID. The `windows | grep` lookup found no matching window and always exited early.

## Fix

Updated `screenshot.sh` to use `BUNDLE_ID=co.sstools.Bluesky.beta`, extracted the bundle ID and app name to variables at the top so they stay in sync with `Configuration/Beta.xcconfig`, improved the error message to include the build command, and added a `--screen <name>` argument that embeds the screen name in the output filename. Added `screenshots-all.sh` as an interactive driver that iterates through all nine key screens (home, thread, profile, search, notifications, messages, composer, settings, moderation), pausing at each for manual navigation before capturing.

## Verification

`windows` tool confirmed present at `/Users/brennan/bin/windows`. Script parses correctly; functional capture requires the Beta app to be running (depends on #0173 to produce a build with the correct bundle ID).

## Files changed

- `screenshot.sh` — fixed bundle ID, extracted constants, added `--screen` arg, improved error message
- `screenshots-all.sh` — new interactive driver iterating through all key screens

## Gotchas

- Fully automated navigation (no-pause iteration) requires the app to register deep link URL handlers per screen — that's a separate task. The current driver pauses for manual navigation, which is sufficient for issue documentation and visual regression work.
- The `windows` tool is at `/Users/brennan/bin/windows` — not a standard system tool. Any CI or other machine running these scripts needs the same binary in `$PATH`.
