# 0191 — Release pipeline: code-signed, notarized, stapled DMG for direct distribution

| | |
|---|---|
| **Status** | open |
| **Module** | Bluesky-SwiftUI / Build / Config |
| **Platform** | macOS |
| **First seen** | 2026-06-10 |

## Description

Stand up the release pipeline that turns the Mac app into a distributable artifact: archive → Developer ID signing (hardened runtime) → Apple notarization → stapling → drag-to-Applications DMG that passes Gatekeeper on a clean Mac → signed Sparkle appcast item. Today the project has none of this — `Build.xcconfig` uses `CODE_SIGN_STYLE = Automatic` with a development team, there is no versioning discipline in xcconfig, and no release scripts exist.

## Expected behavior

A repeatable scripted flow (mirroring Batty's `scripts/` and the `mac-release` skill templates): run a read-only preflight, bump `MARKETING_VERSION`, run the release script, verify the DMG, smoke-test on a clean account — producing `dist/Bluesky-<sha>.dmg` that opens without Gatekeeper warnings on a fresh Mac and an appcast `<item>` ready for the website (#0192).

## Actual behavior

No release path exists; only Debug builds via the Beta/Prod schemes.

## Notes

Implement by adapting the `mac-release` skill templates (`~/.claude/skills/mac-release/templates/`) into `Bluesky-SwiftUI/scripts/`, editing each script's `CONFIG` block (app name, scheme `Bluesky (Prod)`, Team ID `XV8BAAVZ6V`, signing identity, notary profile, workspace path, xcconfig/appcast paths). Batty has a working adaptation to crib from. Scope:

1. **Scripts:** `preflight.sh`, `release.sh`, `verify-dmg.sh`, `appcast-item.sh`, `tag-release.sh`, `setup-notary.sh`, plus a project `RELEASE.md` checklist. Preserve the templates' comments — they encode real failure modes (DMG name = volname, same-day build-number trap, etc.).
2. **Signing:** Developer ID Application cert + hardened runtime for release builds. Current `CODE_SIGN_STYLE = Automatic` is fine for dev; release needs a Developer ID override (likely in `Prod.xcconfig` or release-config only). Mind the entitlements (`Bluesky-SwiftUI.entitlements`, App Group) under the hardened runtime.
3. **Notarization:** App Store Connect API key → `notarytool` keychain profile via `setup-notary.sh` (one-time).
4. **Versioning:** move `MARKETING_VERSION` / version source-of-truth into the xcconfig layer; build number stamped at archive time; keep pbxproj free of overrides. The release script must fail on version drift — this is the top failure mode per the skill (`references/versioning.md`): Sparkle compares build numbers but displays marketing versions, so drift yields "you're up to date" on an old version.
5. **Sparkle release-side:** `sign_update --account Bluesky` signs each DMG; `appcast-item.sh` derives every appcast attribute from the built DMG (never hand-typed). Depends on the keys from #0190.
6. **Tooling prerequisites:** `brew install create-dmg fileicon`; Apple Developer account with Developer ID cert and ASC API key.

**Safety rule from the skill:** notarization submits to Apple and tagging/publishing touch shared systems — those steps are run by the user (or with explicit per-run approval), never autonomously by an agent. Preflight and verify are safe to automate.
