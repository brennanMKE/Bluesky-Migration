# 0217 — `switchAccount` mutates in-memory current account before persisting currentDID

| | |
|---|---|
| **Status** | open |
| **Module** | BlueskyAuth |
| **Platform** | All |
| **First seen** | 2026-06-11 |

## Description

After switching accounts, if persisting the active DID fails (Keychain error), the running app shows the new account active while the next cold launch restores the old one — in-memory and persisted state disagree.

## Evidence

`switchAccount(to:)` (SessionManager.swift:376-382) calls `resumeSession(stored)` first (sets `currentAccount`), then `accountStore.setCurrentDID(did)` (line 381). If `setCurrentDID` throws, `currentAccount` is already the new account while Keychain `current-did` still points at the old one; `restoreLastSession` keys off the persisted DID.

## Suggested fix

Persist `setCurrentDID` before mutating in-memory session state, or roll back `currentAccount` if persistence fails.
