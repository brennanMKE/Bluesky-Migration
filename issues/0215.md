# 0215 — Unsubscribing from a moderation list leaves the row on screen

| | |
|---|---|
| **Status** | open |
| **Module** | BlueskyModeration |
| **Platform** | All |
| **First seen** | 2026-06-11 |

## Description

On the Moderation Lists screen, tapping Unsubscribe on a subscribed mod list fires the call but the row stays visible until a manual refresh or re-navigation — no feedback, and the user may tap again.

## Evidence

`ModerationViewModel.unsubscribe(from:)` (ModerationViewModel.swift:83-90) calls `store.unmuteList`/`unblockList`; those (ModerationStore.swift:469-509) only POST and set `errorMessage`, never touching `subscribedModLists` (private(set)). `ModerationListsScreen.subscribedSection` (110-119) renders straight from that array with no post-action reload, unlike the owned-list delete / mutes-blocks paths which remove optimistically.

## Suggested fix

After a successful unmute/unblock, optimistically remove the list from `subscribedModLists` (revert on error), or re-call `loadModLists()` on success.
