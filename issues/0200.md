# 0200 — Font size setting has no effect outside the Appearance preview

| | |
|---|---|
| **Status** | open |
| **Module** | BlueskyUI / BlueskyKit |
| **Platform** | All |
| **First seen** | 2026-06-10 |

## Description

The **Settings → Appearance → Font Size** tier picker (XS / S / M / L / XL) persists correctly (`appearance.fontSize` in `AppearanceStore`, survives force-quit + relaunch) and re-renders the in-screen preview sentence at the selected body point size — but **nothing else in the app reads the preference**. Feed text, thread text, profile text, etc. render at the same size regardless of the selected tier.

A repo-wide search confirms `AppearanceStore.fontSize` / `AppearanceFontSize.bodyPointSize` have no consumers outside `AppearanceSettingsScreen` (the preview `Text`) and the store itself. The shell modifier (`AppearanceShellModifier` in `Bluesky_SwiftUIApp.swift`) applies `preferredColorScheme` and `blueskyTheme` but never maps the font tier into the environment (e.g. via `.dynamicTypeSize(_:)` or a theme typography scale).

The same applies to the **Font** (System / Theme) family picker: `AppearanceFontFamily` is persisted but never read by the rendering layer (partially by design — no branded font is bundled — but the size tier is supposed to work).

## Steps to reproduce

1. Open Settings → Appearance and note the Home feed's text size.
2. Select **XL** in the Font Size picker. The preview sentence grows (16 → 18 pt).
3. Switch to the Home tab: feed text is unchanged.
4. Pixel comparison of Home-feed screenshots at M and XL shows identical text rendering.

## Expected behavior

Per the Module 14 gate (#0065/#0037): "Drag the Font Size slider … confirm text in the feed reflects it." RN scales app-wide typography from its `fontScale` shell preference through ALF (the font-size tiers in `AppearanceSettings` feed the ALF text atoms), so the selected tier must scale body text across feeds, threads, profiles, and settings. (Local RN checkout is missing from disk — confirm the exact upstream file when wiring the fix.)

## Actual behavior

Only the preview sentence inside `AppearanceSettingsScreen` changes. All other text is fixed at the default scale.

## Notes

- Persistence itself passes: `SettingsGateUITests.testFontSizeImmediateEffectAndPersistence` (#0065) confirms the XL selection survives force-quit + relaunch and the preview scales immediately.
- Likely fix: extend `AppearanceShellModifier` to translate `appearance.fontSize` into the SwiftUI environment — either `.dynamicTypeSize(...)` mapped per tier, or a body-point-size environment key consumed by `BlueskyUI` typography.
- Found while validating #0065 (Module 14 gate, iOS settings persistence).
