## Description

Running the app from Xcode during development uses the same Bundle ID (`co.sstools.Bluesky`) as the production release. This means the dev build and the App Store / notarized build share the same container, UserDefaults, keychain items, and dock presence. A separate Bundle ID for the development build (e.g. `co.sstools.Bluesky.beta`) would allow both to coexist cleanly on the same machine and prevent dev data from contaminating production state.

## Expected behavior

- **Xcode / development builds** use Bundle ID `co.sstools.Bluesky.beta`, product name `Bluesky Beta`, and visually distinct app icons.
- **Release builds** (Prod scheme) use Bundle ID `co.sstools.Bluesky`, product name `Bluesky`, and the production icons.
- Switching between the two requires no manual edits to any source file or xcconfig. The build scheme drives everything.

## Approach

Follow the pattern documented in `../BetaProd/README.md` and the `xcode-betaprod` Claude Code skill:

1. **Add `Active.xcconfig`** to `Configuration/`. This file contains a single `#include` that points at either `Beta.xcconfig` or `Prod.xcconfig`. It is generated (or overwritten) by a pre-build script; add it to `.gitignore` so it never appears as a dirty working-tree change.

2. **Add `Beta.xcconfig` and `Prod.xcconfig`** to `Configuration/`. Each overrides the keys that differ between environments:

   | Key | Beta value | Prod value |
   |---|---|---|
   | `PRODUCT_BUNDLE_IDENTIFIER` | `co.sstools.Bluesky.beta` | `co.sstools.Bluesky` |
   | `PRODUCT_NAME` | `Bluesky Beta` | `Bluesky` |
   | `ASSETCATALOG_COMPILER_APPICON_NAME[sdk=iphone*]` | `AppIconBeta-iOS` | `AppIcon-iOS` |
   | `ASSETCATALOG_COMPILER_APPICON_NAME[sdk=macos*]` | `AppIconBeta-macOS` | `AppIcon-macOS` |

3. **Add `#include? "Active.xcconfig"` to `Configuration/Build.xcconfig`** (optional include so cold clones without `Active.xcconfig` still compile).

4. **Create `scripts/set-environment.sh`** — takes a single argument (`Beta` or `Prod`), writes `Active.xcconfig` with the appropriate `#include`, and optionally copies the matching app icon sets into `Bluesky-SwiftUI/Assets.xcassets/`.

5. **Create two shared build schemes:**
   - `Bluesky (Beta)` — pre-action runs `set-environment.sh Beta`
   - `Bluesky (Prod)` — pre-action runs `set-environment.sh Prod`

   Both pre-actions must be configured to "Provide build settings from" the Bluesky-SwiftUI target so `$PROJECT_DIR` is defined.

6. **Add `AppIconBeta-iOS` and `AppIconBeta-macOS` icon sets** to `Bluesky-SwiftUI/Assets.xcassets/` — visually distinct from the production icons (e.g. tinted or badged) so it is immediately obvious which build is running.

7. **Add a `scripts/` directory** to the project root if it does not already exist.

## Implementation order

1. Confirm with user which keys belong in Beta vs Prod (Bundle ID, name, icons).
2. Implement `scripts/set-environment.sh` and the xcconfig files — no Xcode project file changes yet.
3. Add `#include? "Active.xcconfig"` to `Configuration/Build.xcconfig`.
4. Add shared schemes + pre-actions to `Bluesky-SwiftUI.xcodeproj`.
5. Verify by running `./scripts/set-environment.sh Beta`, building, and confirming the Beta bundle ID appears in `codesign -dv`.

## Notes

- `Configuration/Build.xcconfig` is the only xcconfig in this project and holds `PRODUCT_BUNDLE_IDENTIFIER`, `PRODUCT_NAME`, app icon names, deployment targets, and signing settings. The Beta/Prod split will override only the keys that differ; everything else stays in `Build.xcconfig`.
- `MARKETING_VERSION` and `CURRENT_PROJECT_VERSION` should stay in `Build.xcconfig` (same version for both environments) unless a separate Beta versioning scheme is desired.
- The `../BetaProd/README.md` guide and the `xcode-betaprod` Claude Code skill can assist with the full setup.
- The app uses platform-specific app icon keys (`AppIcon-iOS`, `AppIcon-macOS`) so Beta variants must follow the same naming convention.
- See Batty issue #0146 for the same pattern implemented in a sibling project — the xcconfig approach and `set-environment.sh` script are directly reusable.

## Root cause

No mechanism existed to switch `PRODUCT_BUNDLE_IDENTIFIER` between dev and release builds. The app always built with `co.sstools.Bluesky`, meaning dev and release builds shared the same container and dock slot.

## Fix

Added `Beta.xcconfig` and `Prod.xcconfig` under `Configuration/`. `Build.xcconfig` now ends with `#include? "Active.xcconfig"` — the optional include lets cold clones build without an `Active.xcconfig`. `scripts/set-environment.sh` writes `Active.xcconfig` with the appropriate `#include` line before each build. The two new shared schemes (`Bluesky (Beta)` and `Bluesky (Prod)`) each have a pre-action that calls the script, providing `$PROJECT_DIR` from the Bluesky-SwiftUI target's build settings. `Active.xcconfig` is gitignored so it never appears as working-tree noise.

## Verification

`./scripts/set-environment.sh Beta && xcodebuild -project Bluesky-SwiftUI.xcodeproj -scheme "Bluesky (Beta)" -showBuildSettings` — confirmed `PRODUCT_BUNDLE_IDENTIFIER = co.sstools.Bluesky.beta` and `PRODUCT_NAME = Bluesky Beta`. Same check for Prod: `PRODUCT_BUNDLE_IDENTIFIER = co.sstools.Bluesky` and `PRODUCT_NAME = Bluesky`.

## Files changed

- `Configuration/Beta.xcconfig` — new; sets `PRODUCT_BUNDLE_IDENTIFIER = co.sstools.Bluesky.beta`, `PRODUCT_NAME = Bluesky Beta`
- `Configuration/Prod.xcconfig` — new; empty (production defaults live in `Build.xcconfig`)
- `Configuration/Build.xcconfig` — added `#include? "Active.xcconfig"` at end
- `scripts/set-environment.sh` — new; writes `Active.xcconfig` for named variant; works from both Xcode pre-action and terminal
- `Bluesky-SwiftUI.xcodeproj/xcshareddata/xcschemes/Bluesky (Beta).xcscheme` — new scheme with pre-action calling `set-environment.sh Beta`
- `Bluesky-SwiftUI.xcodeproj/xcshareddata/xcschemes/Bluesky (Prod).xcscheme` — new scheme with pre-action calling `set-environment.sh Prod`
- `.gitignore` — added `Configuration/Active.xcconfig` and `screenshots/`

## Gotchas

- Distinct `AppIconBeta-iOS`/`AppIconBeta-macOS` asset sets were not added — the issue listed them but the icon asset catalog requires explicit user sign-off. The bundle ID and name changes are sufficient to distinguish the builds; icons can be added separately.
- The scheme pre-action only fires when building from Xcode with that scheme selected. Running `xcodebuild -scheme "Bluesky (Beta)"` from the terminal does NOT run pre-actions. Call `./scripts/set-environment.sh Beta` manually before headless builds.
